# Production on Render and Neon, redeploying on every merge to main that runs CI

- Neon project `medication-log-api` created: PostgreSQL 18 (confirmed
  `18.6` via `SELECT version()` in the SQL Editor), region Frankfurt.
  Direct connection string used, pooling off, host without `-pooler`
- `check --deploy` run locally with production-shaped variables, before
  touching either platform: only the known `mail.E001` and the four
  cookie/HSTS warnings appeared, no `DEBUG` warning — confirms the
  platform's environment variables, not `.env`, govern in production
- Render web service `medication-log-api` created: Docker language,
  Frankfurt region, `main` branch, Free instance. Four environment
  variables only: `DATABASE_URL`, `DJANGO_SECRET_KEY` (generated by
  Render, never seen locally), `DJANGO_ALLOWED_HOSTS`, `PORT=8000`.
  `DJANGO_DEBUG` left unset, defaulting to `False`
- Health Check Path `/healthz/`. Docker Command runs `migrate --noinput`
  before `exec granian`, so a failed migration keeps the previous
  version live instead of starting a broken one
- First deploy succeeded: migrations applied in order, Granian
  listening, service live at `https://medication-log-api.onrender.com`
- Production `/healthz/` verified from outside: `200` over HTTPS with
  the database check `ok`; plain HTTP redirects to HTTPS. `/admin/`
  reachable, unstyled, no account to sign in with — as decided
- `migrate --check` run from the local machine directly against Neon:
  exit code `0`, no pending migration
- Auto-Deploy switched to **After CI Checks Pass**
- `.env.example` changed to document where production values live and
  that `PORT` is Render-managed; committed on its own branch and opened
  as a pull request, so the three required CI checks would run against
  a real, non-documentation change
- Pull request merged with **Squash and merge**, matching the
  one-commit-per-pull-request history already on `main` — a plain
  "Merge pull request" would have introduced the project's first merge
  commit
- Confirmed the deploy that followed only started after the CI run on
  `main` finished, and was Render's own automatic trigger, not a manual
  one — proving "After CI Checks Pass" is what actually governs
- Branch deleted, locally and on GitHub, after confirming `main`
  matched the merged commit
- Hibernation observed after more than 20 minutes idle: Neon's compute
  showed `Idle` beforehand; the next request took about 40 seconds, and
  the Render log shows the migration check running again
  (`No migrations to apply.`) before Granian starts

**What this locks in for the rest of the project:** production answers
publicly at `https://medication-log-api.onrender.com/healthz/`, backed
by the real Neon database, and every merge to `main` that runs the CI
workflow redeploys on its own — not every merge: a documentation-only
merge skips CI under `paths-ignore`, and Render detects no check to
wait for, so it does not publish. This corrects the roadmap's original
line 0.11 ("redeploying on every merge to main") to what was actually
built.
